## 3. 入力項目
既存の `game_count`・`total_game_count`・打-WIN取り込み欄・ヒント欄は流用。追加フィールド（repositoryに保存）:
- `at_count`: AT初当たり回数
- `cz_remi_count`: レミニセンス回数
- `cz_rize_count`: 大喰いの利世回数
- `episode_count`: エピソードボーナス回数
- `replay_direct_count`: リプレイからのAT直撃回数
- `lower_replay_count`: 下段リプレイ回数（任意）
- `cz100_log`: 「100G以内にCZに当選したか」を1件ずつ記録。`[{ id, win: boolean }]`
  （ボタン「100G以内にCZ当選」「100G以内にCZ外れ」。押すたび自動保存、×で削除）
- `pullback_log`: AT終了ごとの引き戻し結果。`[{ id, win: boolean }]`
  （ボタン「引き戻し当選」「引き戻し失敗」。押すたび自動保存、×で削除）
- 空欄=未計測は計算に使わない。0と区別する（`optionalCount` のやり方）。

## 4. buildEstimate
カバネリの `buildEstimate` と同じ呼び方で `estimateSettingLikelihoods(samples)` に渡す。samples:
- AT初当たり（k=`at_count`, n=`game_count`）
- レミニセンス、大喰いの利世、エピソード、リプレイ直撃、下段リプレイ（それぞれ k=回数, n=`game_count`）
- 100G以内CZ当選（k=win件数, n=総件数, rates=100G以内のCZ当選率）
- 引き戻し（k=win件数, n=総件数, rates=引き戻し当選率）
- 示唆は `hintMinSetting` と `excludedSettings` に反映（尤度には混ぜない）。

`observedMetrics` は各要素の実測値（分数表示 or %）。フォームの推定パネルはカバネリ分の表示処理を共通化して使い回してよい（機種ごとに複製しない）。
