## 3. 入力項目（観測記録の1件=台に座った1回）
既存の `game_count`（通常ゲーム数）、`total_game_count`、打-WIN取り込み、ヒント欄は流用。追加フィールド:
- `bonus_count`: ボーナス初当たり回数
- `st_count`: ST突入（初当たり）回数
- `bell_count`: 下段ベル回数（ゲーム数とあわせて確率計算）
- `kage_log`: 復讐の炎成功のたびに記録。`[{ id, ura: boolean }]`（裏景之ST=true / 真景之ST=false）。1件ごとに自動保存。
- `period_log`: 周期メモ。戦国乙女5と同形式 `[{display_game, hit}]`。
  カバネリは周期3・4の当選率だけを推定に使うので、集計関数 `summarizePeriodStats(period_log)` を返す:
  「N周期目に到達した回数」「N周期目で当選した回数」（N=1..）。当選したら次は1周期目から数え直す。
- 示唆チェック（任意、`SETTING_HINTS`として戦国乙女5と同じ形で持つ）:
  - ST終了画面「無名＋菖蒲（水着）」→ 設定6濃厚
  - おみくじ: 大吉=設定6 / 中吉=設定4以上 / 小吉=設定2以上 / 来栖の刀=設定2・3否定
  - ボイス「やっぱりこの台……普通じゃないね」=設定2以上、（ボーナス中にボイスが一度も出ない=設定5以上、**要確認: 母数不明のため参考表示のみ**）
  - サミートロフィー: 虹=設定6 / キリン=設定5以上 / 金・銀・銅は参考
  - 獲得枚数表示: 666 OVER=設定6 / 456 OVER=設定4以上（`PAYOUT_OVER_HINTS`）
- `ENDING_STAMPS` はカバネリの終了画面で使えるものだけ（上記）。無ければ空配列でフォームがカードを出さないこと。

## 4. buildEstimate の計算
`js/logic/settingInference.js` の既存の尤度関数を使う（戦国乙女5の `buildEstimate` を読んで同じ呼び方に）。
- ボーナス: `bonus_count` / `game_count`
- ST: `st_count` / `game_count`
- 下段ベル: `bell_count` / `game_count`（`bell_count` が空欄なら計算に使わない。0と空欄は区別）
- 周期3: 「3周期目に到達した回数」中の当選回数、周期4も同様
- 景之: `kage_log` の裏=true の回数 / 総件数
- 示唆は `hintMinSetting` に反映（尤度には混ぜない）
- 数値が空欄の要素は**計算から外す**（0扱いにしない）
